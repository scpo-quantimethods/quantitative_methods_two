Session 2 : logistic regressions

Motivation

In the previous session and in our exercises, we discussed cases where our dependent variables were continuous. These included the vote share for the far-right in French communes, the median income in those communes, and party positions from the Chapel Hill survey (scaled and averaged from 1 to 10).

However, at the end of the class, we also observed that one of our results exhibited heteroskedasticity, and that plotting the residuals against the fitted values revealed some unusual shapes in the plot. This issue arises because our dependent variable, the share of votes in a commune, is bounded between 0 and 1. By default, a linear regression model does not account for these bounds, which can lead to inconsistent results (e.g., extending the regression line beyond 1, which is impossible for a share of votes), and heteroskedasticity. In situations where the dependent variable is binary, as is often the case in political science (e.g., whether someone voted or not), applying a linear regression model would violate several assumptions of the model. This is why we use logistic regression.

In practice, many dependent variables in political science are binary. A typical example is when we want to determine whether an individual voted for a particular party, or whether they voted at all. Using linear regression to analyze such variables would yield absurd results and would violate multiple assumptions underlying the model.

For this reason, we use other types of regressions to perform such analyses. The one we will explore today is particularly suited for binary outcomes (TRUE/FALSE or 1/0 outcomes). This is called logistic regression. You should have seen the theory behind these regressions with Prof. Rovny, but if you need a reminder, please go the last sections of this page.

The objectives of this session are :

  1. Cleaning data: dropping rows, columns, creating and mutating variables
  2. Building a generalized linear model (glm()); special focus on logit
  3. Extracting and interpreting the coefficients
  4. Visualization of results

We will be working with the European Social Survey (ESS), the largest, most comprehensive, and arguably one of the most important surveys on social and political life within the European Union. Learning how to handle, manage, and clean the ESS data will equip you with the skills to work with virtually any dataset you encounter. As already said, we’ll focus on voter turnout. Our goal is to understand what factors encourage people to vote and what decreases the likelihood of voting on election day. Therefore, the question for our dependent variable will be: Did the respondent vote or not? Mathematically, this question cannot be answered using linear regression with the OLS method, as the dependent variable is binary—0 represents “did not vote” and 1 represents “voted.” There are only two possible outcomes, and the variable is not continuous, which violates one of the assumptions of OLS.

However, if we use the voting turnout variable as it is right now, we won’t have a valid binary variable. It also won’t be reliable, as it includes values that are either irrelevant or will skew our estimations. In fact, logistic regression (logit) can only be applied to binary variables.

So, before we proceed, we need to transform our dependent variable. We’ll remove unwanted values and convert the 1s and 2s into 0s and 1s.

First, we need to eliminate the values we’re not interested in. While it’s possible to filter out these values directly (as shown below), I recommend against it. Instead, you should transform these values into NA. Rows with NA values will be excluded from the regression, but if you later decide to run another model with a different dependent variable, you may lose valuable observations that you’ve filtered out. Therefore, a good rule of thumb is to only filter out values if you’re certain you’ll never need them again.

ess <- ess |>
  filter(!vote %in% c(3, 7, 8, 9))

We can directly mutate the values within the variable using case_when() inside the mutate() function. While case_when() may seem a bit tricky to read at first, it’s a powerful tool. Essentially, case_when() evaluates a series of conditions and applies the corresponding transformation to each element of a vector or column in a dataset.

Within the function, you must specify at least one condition, and you can include multiple conditions if needed. If you want the conditions to be evaluated simultaneously, use the & operator between them. If you want the condition to apply when either of two conditions is true, you would use the |`` operator. After specifying the conditions, you use a tilde~`, followed by the new value that the variable should take on if the condition is met.

Here’s how it works:

case_when(
  condition1 ~ value_if_true1,
  condition2 ~ value_if_true2,
  TRUE ~ default_value
)

Let’s look at an example below. I want the values 3, 7, 8, and 9 in the vote variable to be replaced with NA, as they are irrelevant to our analysis. To do this, we use the mutate() function, and I assign a new column (which I’ll name vote, the same as the original variable). Inside the case_when() function, I specify vote %in% c(3, 7, 8, 9) ~ NA_integer_. This statement means: whenever vote contains the values 3, 7, 8, or 9, replace them with NA_integer_.

The next line, TRUE ~ vote, serves as a catch-all rule. It says, “For all other cases, keep the original values of vote.” This ensures that any value not matching the previous condition remains unchanged.

Here’s the code:

ess <- ess |> 
  mutate(
    vote = case_when(
      vote %in% c(3, 7, 8, 9) ~ NA_integer_,
      TRUE ~ vote
  ))
table(ess$vote)

    1     2 
23529  7132

Now, we just need to transform the ones and twos into zeros and ones. This is both a matter of convention, my personal coding preference, and, of course, to give you a bit more practice with data management. Since we are focusing on people who have voted, we’ll code those who voted as 1 and those who didn’t as 0.

We’ll use case_when() again to do this. The code case_when(vote == 1 ~ 1, vote == 2 ~ 0) works as follows: whenever vote equals 1 (indicating that the person voted), we keep it as 1; whenever vote equals 2 (indicating that the person did not vote), we assign it 0.

With that, we now have our binary dependent variable, which is essential for performing a logit. The table() function will show that we’ve successfully changed the values of the variable, but the total count remains the same.

In Base R, you could achieve this in a different way, but I personally find that using the mutate() function is the most elegant approach. That said, it’s entirely up to you which method you prefer.

# only use the ifelse() function
ess$vote <- ifelse(ess$vote == 1, 1, 0)

# This will leave the value of 1 at 1 and change 2 to 0 for the column vote.
ess$vote[ess$vote == 1] <- 1
ess$vote[ess$vote == 2] <- 0

We’re very close to finishing the data management part and getting ready to work on our model. However, there are still many variables that are as “untidy” as our initial dependent variable. We need to check the codebook to see if there are specific values we can’t simply replace across the entire dataset and whether they are still irrelevant to our analysis.

For our independent variables of interest, here’s what we need to do:

  • Political interest (polintr): Remove values c(7:9).
  • Trust in politicians (trstplt): No recoding needed (unwanted values are already NA).
  • Trust in political parties (trstprt): Already done.
  • Feeling close to a party (clsprty): Convert 1/2 to 0/1 and remove values c(7:8).
  • Gender (gndr): Convert to 0/1 and remove “no answer” values.
  • Year born (yrbrn): Already done.
  • Years of full-time education completed (eduyrs): Already done.

We’ll tackle all these steps at once using pipes %>% (from the tidyverse) or |> (Base R), which allows us to perform everything in a neat and efficient way. I’ll also re-run the mutation for our dependent variable to demonstrate the flexibility of long pipe chains.

We start by using mutate() to adjust the independent variables we need for our model. Notice how you can separate the different manipulations with commas inside the same function, which results in clean, readable code. There are various functions for data wrangling, such as recode(), if_else(), and case_when(). For simplicity and clarity, I’ll be using case_when() here, though there’s a newer function, case_match(), that you could also use.

Now, let’s talk about NA_integer_. In R, NA signifies “not available” or missing data. But R is very particular about the type of data it’s working with. If your variable is numeric, you need to specify that missing values should be treated as numbers. By using NA_integer_, you’re telling R, “This is missing data, but if it were here, it would be a number.” This ensures consistency and avoids confusion when R processes your data. If you’re working with character strings, you’d use NA_character_. For numeric values with decimals, you’d use NA_real_ instead of NA_integer_.

ess_final <- ess |> 
  # mutating the dependent variable to get rid of any unnecessary rows
  # as we have done above
  mutate(
    vote = case_when(
      vote %in% c(3, 7, 8, 9) ~ NA_integer_,
      vote == 2 ~ 0,
      vote == 1 ~ 1, 
      TRUE ~ vote
    ),
    # Recode 'polintr' to drop values 7 to 9
    polintr = case_when(
      polintr %in% c(7:9) ~ NA_integer_,
      TRUE ~ polintr
    ),
    # Recode 'clsprty' 1/2 into 0/1 and drop 7, 8
    clsprty = case_when(
      clsprty == 1 ~ 0,
      clsprty == 2 ~ 1,
      clsprty %in% c(7, 8) ~ NA_integer_,
      TRUE ~ clsprty
    ),
    # Recode 'gndr' into 0/1 and handle other cases as NAs
    gndr = case_when(
      gndr == 1 ~ 0,
      gndr == 2 ~ 1,
      TRUE ~ NA_integer_
    ),
    # recode eduyrs
    eduyrs = case_when(
      eduyrs %in% c(1:55) ~ eduyrs,
      TRUE ~ NA_integer_
    ),
    # this one is very advanced...
    across(c(trstplt, trstprt), ~case_when(
      .x <= 10 ~ .x, 
      TRUE ~ NA_integer_
    ))
  )

Running the model

Once the data preparation is done, the best part is that running a logistic regression model literally takes just one line (or two, depending on the number of independent variables). As you’ll see, it’s quite straightforward.

The glm() function, which stands for generalized linear model, is a part of Base R.

In Professor Rovny’s lecture, we discussed that for Maximum Likelihood Estimation (MLE), you need to know or assume the distribution of your dependent variable. Based on that distribution, you choose the appropriate linear model. For a binary outcome like voting (yes/no), the distribution is binomial. So, within the glm() function, we specify the distribution family as binomial.

It’s worth mentioning that you can specify other families, such as Gaussian, Poisson, or Gamma, depending on your data. We won’t go into detail about those families here, but the glm() function is quite powerful. By setting family = binomial(link = "logit"), we specify that we’re conducting a logistic regression. If you wanted to use a different link, such as probit or cauchy, you can easily adjust it here. The default is set to logit, so in most cases, you won’t need to specify it explicitly.

If your dependent variable is incompatible with the chosen family, the function will alert you to a problem.

For the model we’re building, we’re assuming that voting behavior (whether a person voted or not) is influenced by political interest, trust in politicians, trust in political parties, and feeling close to a party, along with typical control variables like gender, age, and education.

Please note that this regression isn’t sophisticated enough to be published—it’s simply an example. My hypothesis is that factors like political interest, trust in politics and politicians, and party affiliation are key explanatory variables.

Just like with an OLS regression, we start by specifying the dependent variable (in this case, vote). Then, we separate the dependent variable from the independent variables with a ~. Next, we list the predictors, separated by a +. Finally, we specify the data object and the model family.

Here’s how you can run the model:

logit <- glm(
  vote ~ polintr + trstplt + trstprt + clsprty + gndr +
    yrbrn + eduyrs,
  data = ess_final,
  family = "binomial")

The object we created, called logit, now contains our model along with its coefficients, confidence intervals, and many other details that we’ll explore further! As you can see, the actual process of constructing the model is incredibly simple and only requires a single line of code.

Now that we’ve created the model, we can examine its components and assess how well it fits our data. The logistic regression model has produced outputs that we can use to make inferences about the relationship between our dependent and independent variables. The simplicity of the code doesn’t mean that the analysis is complete—it’s just the beginning of our exploration!

Interpretation of logistic regression

Interpreting the results of a logistic regression can initially feel challenging because the model predicts probabilities rather than direct outcomes. This may seem abstract at first. However, once you understand how to interpret the coefficients and odds ratios, it becomes much easier to see how the independent variables relate to the binary outcome—without necessarily transforming the coefficients into more intuitive values.

The odds ratio

To properly understand the logit, we first need to clarify what it represents: it is the logarithm of the odds. The odds themselves are defined as the ratio between the probability that an event occurs, \(p\), and the probability that it does not occur, \(1-p\).

\[\begin{equation} \text{ODDS} = \frac{p}{1-p} \end{equation}\]

In other words, the odds tell us how much more (or less) likely the event is to happen than not to happen. For example, if an event has a probability of 0.1, its odds are:

\[\begin{equation} \text{ODDS} = \frac{1/10}{9/10} = 1/9 \end{equation}\]

This means the event is nine times less likely to occur than not to occur.

If the probability is 0.8, then the odds are:

\[\begin{equation} \text{ODDS} = \frac{8/10}{2/10} = 4, \end{equation}\]

which means the event is four times more likely to happen than not to happen. Notice that when the probability equals 0.5—meaning the event is equally likely to occur or not—the odds equal 1.

Importantly, the odds are always positive and increase very rapidly as \(p \rightarrow 1\). To obtain a more symmetric and analytically convenient measure, we usually take the natural logarithm of the odds. The logit is therefore defined as:

\[\begin{equation} \ln(\text{ODDS}) = \ln\left(\frac{p}{1-p}\right) \end{equation}\]

Unlike the odds, the logit can take any real value, positive or negative. The differences betweens the odds ratio function, the logit, and the logistic functions are shown in the panel below.

  • Odds ratio
  • Logit function
  • Logistic function
p <- c(1:10000)/10000 # probabilities 0.0001, 0.0002, 0.0003,... 0.9998, 0.9999
plot(p, p/(1-p)) # odds
plot(p, log(p/(1-p))) # logit
x <- c(1:10000)
mu <- 5000
s <- 500
plot(x, exp((x-mu)/s)/(1+exp((x-mu)/s))) # logistic function

Now, suppose that the probability \(p\) follows a logistic function of some variable \(x\) (for instance, \(p\) could represent the probability of voting, and \(x\) a person’s income). Then we can write:

\[\begin{equation} p(x) = \frac{1}{1 + e^{- (\beta_0 + \beta_1 x)}} \end{equation}\]

Taking the logit of this expression yields a simple linear relationship:

\[\begin{equation} \text{logit}(p(x)) = \beta_0 + \beta_1 x. \end{equation}\]

This expression corresponds to the log of the odds. By exponentiating the logit, we recover the odds:

\[\begin{equation} \text{ODDS} = e^{\text{logit}(p(x))} = e^{\beta_0 + \beta_1 x}. \end{equation}\]

Therefore, a change \(\delta x\) in \(x\) leads to a multiplicative change of \(e^{\beta_1 \delta x}\) in the odds. This makes interpretation straightforward: depending on the sign of \(\beta_1\), the event becomes more or less likely to occur.

The logistic regression

In logistic regression, coefficients represent the change in the log-odds of the outcome for a one-unit increase in the predictor variable, while holding all other variables constant. The sign of the coefficient indicates the direction of the relationship:

  • A positive coefficient means that as the predictor increases, the odds of the outcome increase.

  • A negative coefficient means that as the predictor increases, the odds of the outcome decrease.

To make interpretation more intuitive, we often convert coefficients into odds ratios by exponentiating them (this simply reverses the logarithm). The odds ratio represents how the odds of the outcome change for a one-unit increase in the predictor variable compared to a reference value.

  • An odds ratio greater than 1 indicates a positive association.

  • An odds ratio less than 1 indicates a negative association.

It is also important to remember that logistic regression relies on certain assumptions, including linearity in the logit, independence of observations, and appropriate model specification. Violations of these assumptions can affect both model performance and interpretation. We will revisit diagnostic checks for logistic regression models in a later session.

I know this may sound dense. It is somewhat technical, but it becomes much clearer once we apply the concepts to our actual model. Interpreting exponentiated coefficients as odds ratios will also make the results much more intuitive.

Looking at our model summary, we can already see that most independent variables are statistically significant (p < .05). Typically, we focus our interpretation on statistically significant variables and do not interpret those that are not significant.

From the results, we observe that closeness to a party and age are negatively associated with voting behavior. This makes sense given how the variables are coded. According to the codebook, higher values represent respondents who are less interested, less close to a party, or older (depending on the coding). Therefore, higher values correspond to a lower likelihood of voting on election day.

Trust in politicians, however, is coded in the opposite direction. Higher values indicate lower trust. As a result, the positive coefficient suggests that lower trust in politicians increases the likelihood of not voting. Ideally, it would have been better to code all independent variables in the same direction for easier interpretation, but the results can still be interpreted correctly as long as we carefully consider the coding scheme.

Predicted probabilities

Overall, we could now present a table with the odds ratios and move on to writing the paper. However, visualizing results often tells a much clearer and more compelling story. In this section, I will show you how to compute predicted probabilities and how to display them in an effective and visually appealing way.

In logistic regression, predicted probabilities represent the likelihood that an event occurs given specific values of the predictor variables. Rather than interpreting log-odds or odds ratios—which can feel abstract—predicted probabilities provide a simple number between 0 and 1. For instance, instead of stating that higher political interest increases the log-odds of voting, we can say that an individual with high political interest has a 75% probability of voting. This makes the results far more intuitive and easier to communicate.

Predicted probabilities are expressed on the original scale of the independent variables (IVs). This means they directly illustrate how changes in variables—such as political interest, trust in politicians, or education—affect the probability of the outcome. If political interest is measured on a scale from 1 to 4, we can examine how the probability of voting changes at each level of that scale, rather than simply noting whether the relationship is positive or negative. This is a major advantage over coefficient plots, which show direction and magnitude but not the actual likelihood of the outcome. Predicted probabilities therefore allow us to present findings in a way that is both intuitive and closely tied to the real-world measurement of our variables.

The key idea is that we select one predictor variable and decide the values at which we want to estimate the outcome. While doing so, we “hold the other independent variables constant.” This allows us to isolate the effect of the variable we are interested in.

To make this absolutely clear: when calculating predicted probabilities, we focus on one independent variable of interest and keep all other variables fixed—typically at their mean or median, or, in the case of a dummy variable, at one of its two possible values. By holding the other variables constant, we can clearly observe the independent effect of the predictor we care about.

Automating processes

In programming, it often takes time to fully understand and apply new concepts. Once we become comfortable with a process, the next logical step is to think about how to automate it. Automation helps make our work faster, cleaner, and more efficient. After we understand a workflow well, we can usually transfer and automate it in other contexts with relatively little effort.

Take today’s logistic regression as an example. We worked with the ESS data and analyzed the 10th round for France, examining which variables predict abstention. But we could just as easily ask the same research question across multiple waves of the ESS or across multiple countries. If I asked you to run the same logit model for all ESS countries, your first instinct might be to copy and paste your code for each country. However, this would quickly lead to a very long and inelegant script—and the longer the code, the greater the risk of making mistakes.

A good rule of thumb in programming is this: if you find yourself repeating the same steps multiple times, and only a few elements (such as variable names or country identifiers) change, then the task can likely be automated. At some point, the goal should be to build a workflow—or pipeline—that allows your code to run as automatically and efficiently as possible.

In RStudio, there are several ways to achieve this. For example, you can use for-loops to perform the same operation sequentially over a list of elements. Alternatively, you can write your own functions. After all, functions such as glimpse() or read_csv2() were written by someone at some point. As R users, we can do the same. By creating our own functions, we can bundle multiple operations together and then apply them to several objects or subsets of a dataset—such as different countries—at once.

Everything that follows is optional, but I think it is important that you are exposed to these ideas early on. Some of you may already feel confident enough to experiment with automation on your own. If not, that is completely fine—you will get there. My goal here is simply to show you what is possible and to give you a sense of what you can achieve with R.

The purrr package

The purrr package in R is a powerful tool for handling repetitive tasks in a more efficient and elegant way. It is part of the Tidyverse, a collection of R packages designed to make data science faster, more intuitive, and more enjoyable.

In simple terms, purrr improves how we work with lists and vectors in R. It provides functions that allow us to apply operations—whether built-in functions or ones we write ourselves—to each element of a list or vector without explicitly writing loops. This approach is known as functional programming.

Put differently, the functions in purrr enable us to systematically apply a function to every element of a list or vector. Depending on which purrr function we use, the resulting output may differ (for example, returning a list, a vector, or a data frame). We can also control the structure of the output within the custom function that we pass to purrr, giving us both flexibility and efficiency.

The map function

The map() function from the purrr package in R is based on a straightforward but powerful idea: it applies a function to each element of a list or vector and returns a new list containing the results. This process is called mapping, which is why the function is named map().

  • Input: The main input to map() is a list or vector: in this example, the list with numbers (1,2,3,4,5). This can be as simple as a list of numbers or characters, or more complex objects like vectors within lists or even data frames.

  • Function Application: You provide a function that you want to apply to each element of the input. Here, the function is sqrt (square-root). This function can be a built-in R function or one you’ve written yourself. The important point is that it will be applied separately to each element of the list or vector.

  • Iteration: map() automatically iterates over each element of your input. There’s no need to write a loop—the function takes care of this internally. For each element, map() applies the function you specified.

  • Output: The results of the function applied to each element are collected into a new list. Each element of the output list corresponds to the result of the function applied to the respective element of the input.

  • Flexibility in Output Type: purrr offers specialized versions of map() to control the type of output. For instance, map_dbl() returns numeric values (doubles), map_chr() returns character vectors, and so on. This ensures that the output matches the type you expect, making subsequent analysis easier.

Concept of logistic regression

The maximum of likelihood estimation

Constant probabilities

Suppose you are interested in the outcome of a binary event, where the probability of the event occurring is \(p\) and the probability of it not occurring is \(1 - p\). This follows Bernoulli’s probability distribution:

\[\begin{equation} P(X = x) = p^x (1-p)^x \ \text{with} X \in \{0, 1\} \end{equation}\]

For example, imagine rolling a fair six-sided die. The probability of rolling a 1 (i.e., \(X = 1\)) is \(p = 1/6\), and the probability of rolling anything other than a 1 (i.e., \(X = 0\)) is \(1 - p = 5/6\). Many research questions involve finding such probabilities for binary outcomes, such as understanding why people vote or abstain, or why they vote for a particular party. These are binary outcomes, and calculating their probabilities using linear regression would not be appropriate.

Suppose you observe \(N\) independent binary outcomes, each determined by an unknown probability \(p\). Let \(n_1\) represent the number of outcomes where \(X = 1\), and \(N - n_1\) the number of outcomes where \(X = 0\). The likelihood function is:

\[\begin{equation} \mathcal{L}(p) = \prod_i^{n_1} (p_i) \prod_i^{N-n_1} (1-p_i) = p_i^{n_1}(1-p_i)^{N-n_1} \end{equation}\]

This expression represents the probability of obtaining \(X = 1\) \(n_1\) times, multiplied by the probability of obtaining \(X = 0\) \(N - n_1\) times. If you do not know the probability \(p\) but have the outcomes for a large number of observations, you can estimate \(p\) by maximizing the likelihood function. This method is called .

A simple example

Let’s say you’re interested in estimating the probability of rolling a 1 on a fair die, but you don’t know the probability (which you know theoretically to be 1/6). Let \(X = 1\) if you roll a 1 and \(X = 0\) otherwise. The probabilities are:

\[\begin{equation} P(X=1) = 1/6 = p_1 \end{equation}\]

and \[\begin{equation} P(X=0) =5/6 = p_0 = 1-p_1 \end{equation}\]

You roll the die 10,000 times and want to estimate \(p_1\). The likelihood function for these observations would be:

\[\begin{equation} \mathcal{L} = \Pi_i^{n_1} (p_i) \Pi_i^{10000-n_1} (1-p_i) \end{equation}\]

You would typically compute the likelihood function as: \[\begin{equation} \mathcal{L}(p) = \Pi_i^{n_1} (p_i) \Pi_i^{10000-n_1} (1-p_i) = p_i^{n_1} (1-p_i)^{10000-n_1}. \end{equation}\] The goal is to maximize the likelihood function to find the value of \(p\) that makes the observed data most probable. To do this, take the log of the likelihood function:

\[\begin{equation} \text{log}(\mathcal{L}(p)) = \text{log}(\Pi_i^{10000} (p_i) \Pi_i^{10000} (1-p_i)) = \text{log}(p_i^{N_1})+\text{log}((1-p_i)^{10000-N_1 \end{equation}\]

which gives :

\[\begin{equation} \text{log}(p_i^{N_1})+\text{log}((1-p_i)^{10000-N_1}) = N_1 \text{log}(p_i) + (10000-N_1)\text{log}(1-p_i) \end{equation}\]

Next, differentiate with respect to \(p\): \[\begin{equation} \frac{d\text{log}(\mathbb{L}(p))}{dp} = \frac{n_1}{p} - \frac{10000 - n_1}{1 - p}. \end{equation}\] Set the derivative equal to zero to solve for \(p\): \[\begin{equation} \frac{n_1}{p} = \frac{10000 - n_1}{1 - p}. \end{equation}\]

This simplifies to: \[\begin{equation} p = \frac{n_1}{10000}. \end{equation}\]

This result is simply the proportion of 1’s in the 10,000 rolls, which is the maximum likelihood estimate of the probability. According to the law of large numbers, as \(N \to \infty\), this estimate will converge to the true probability \(p\). Thus, maximizing the likelihood function allows us to estimate the probability distribution that best fits the data.

Non-constant probabilities

Now imagine that your probabilities depend on other explanatory variables \(x_1, x_2, x_3\). For example, in a research study seeking to understand voter behavior, the probability of an individual voting might depend on their income, gender, or political affiliation. In this case, you would seek to estimate the relationship between these variables and the outcome of voting.

The likelihood function in this case would be:

\[\begin{equation} L(x_1, x_2, x_3) = \Pi_{i\ (y_i = 1)}^n p(x_1, x_2, x_3)_i \Pi_{i\ (y_i = 0)}^n (1 - p(x_1, x_2, x_3))_i \end{equation}\]

In the simpler case where only one explanatory variable \(x\) is considered, the likelihood function is:

\[\begin{equation} L(x) = \Pi_{i\ (y_i = 1)}^n p(x)_i \Pi_{i\ (y_i = 0)}^n (1 - p(x)_i) \end{equation}\]

which you would maximize to find the parameters that best fit the data.

Logistic function

The logistic function is : \[\begin{equation} p_L (x) = \frac{1}{1+ e^{-(\beta_0 + \beta_1 x)}} = \frac{1}{1+e^{-(x-\mu)/s}} = \frac{e^{(x-\mu)/s}}{1+e^{(x-\mu)/s}} \end{equation}\] and it is strictly bounded between 0 and 1, which is expected for a probability.

x <- c(1:10000)
mu <- 5000
s <- 500
plot(x, exp((x-mu)/s)/(1+exp((x-mu)/s)))

You can use this logistic function in the likelihood function: \[\begin{equation} \mathcal{L}(x) = \Pi_{i\ (y_i = 1)}^n p(x)_i \Pi_{i\ (y_i = 0)}^n (1 - p(x)_i), \end{equation}\] maximize it, and find the parameters \(\beta_0\) and \(\beta_1\) that best fit your data.

This is the logic behind maximum likelihood estimation: you assume your probability follows a certain distribution (in this case, the logistic distribution), and then estimate the parameters that maximize the likelihood of obtaining your data. This is precisely what the glm function in R does when it fits a logistic regression model — it computes the parameters that maximize the likelihood function using numerical methods.

Logit

The logit is the inverse of the logistic function. It is defined as: \[\begin{equation} \text{logit}(p(x)) = \ln (\frac{p(x)}{1-p(x)}) = \beta_0 + \beta_1 x, \end{equation}\]

The logit is the inverse of the logistic function. It is defined as:

\[\begin{equation} \text{logit}(p(x)) = \ln \left( \frac{p(x)}{1-p(x)} \right) = \beta_0 + \beta_1 x, \end{equation}\]

In other words, the logit is the logarithm of the odds. The odds is simply the ratio ($ $ ), and gives a real number that tells you how many times more likely (or less likely) you are to obtain the outcome. For example, if the probability of an event occurring is 20% (i.e., ($ p = 0.2 $)), the odds are: \[\begin{equation} \text{odds} = \frac{0.2}{1 - 0.2} = 0.2 / 0.8 = 0.25. \end{equation}\] This means the event is 4 times less likely to happen than not to happen.

On the other hand, if the probability of an event occurring is 80% (i.e., ($ p = 0.8 $)), the odds are: \[\begin{equation} \text{odds} = \frac{0.8}{1 - 0.8} = 0.8 / 0.2 = 4. \end{equation}\] This means the event is 4 times more likely to happen than not to happen.

When considering probabilities between 0 and 1, the odds function (\(\frac{x}{1-x}\)) increases very rapidly as the denominator approaches zero. This is why the log of the odds (the logit) provides a more manageable and continuous scale. For a visual comparison, here’s a plot in R showing the relationship between the probability (\(p\)) and the odds, as well as the logit :

p <- c(1:10000)/10000
plot(p, p/(1-p))
plot(p, log(p/(1-p)))

Hence, you see that the logit associates every probability \(p\) with a continuous variable. In the special case where the probability \(p\) is a logistic function of variables \(X_1, X_2, \dots, X_k\), we can express this relationship as:

\[\begin{equation} \text{logit}(p | x_1, x_2, x_3) = \ln \left( \frac{p}{1 - p} \right) = \beta_0 + \beta_1 x_1 + \beta_2 x_2 + \beta_3 x_3. \end{equation}\]

This is why you can obtain the odds by simply exponentiating the logit, which essentially gives you the odds ratio. In other words:

\[\begin{equation} \text{ODDs} = \frac{p}{1 - p} = e^{\text{logit}(p)} = e^{\beta_0 + \beta_1 x_1 + \beta_2 x_2 + \beta_3 x_3}. \end{equation}\]

Any variation \(\delta x_1\) in the explanatory variable \(x_1\) leads to a change in the odds:

\[\begin{equation} \delta \text{ODDs} = e^{\beta_1 \delta x_1}. \end{equation}\]

This means that any change in \(x_1\) results in a multiplicative change in the odds of the outcome occurring. The model allows you to compute the probability that best characterizes your process and helps to understand how each explanatory variable influences the outcome.

Now, if you decide that \(p\) is a function of other variables \(x_1, x_2, x_3\), you need a function that associates these real numbers with probabilities that range from 0 to 1. This is exactly what the logistic regression model does — it provides a way to model the relationship between the independent variables and a binary outcome, ensuring that the probabilities stay within the valid range of 0 and 1.

But now, imagine you want to understand what drives the probability. In other words, you want to know how different factors (i.e., the explanatory variables) affect the likelihood of the outcome. The logistic regression model, through maximum likelihood estimation, gives you the answer to this question by estimating the coefficients \(\beta_1, \beta_2, \dots, \beta_k\), which tell you the effect of each variable on the log-odds of the outcome.
